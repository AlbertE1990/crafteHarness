# ADR-0006：Agent 默认装载安全内置工具

- 文档类型：架构决策
- 状态：Accepted
- 日期：2026-09-08

## 背景

`get_current_time` 和 `calculator` 已由 CraftAgent 提供，但此前仍要求每个 Runtime 导入工厂、创建实例并加入
工具数组。这使“内置工具”与应用工具没有实际区别，增加样板代码，也容易让示例 Runtime 被误认为内置工具
的所有者。

单纯把 `tools?: AgentTool[]` 改成自动追加又会产生歧义：调用方无法表达这个数组是在扩展默认集合，还是要
建立严格白名单并完全替换默认集合；同名工具还可能发生静默覆盖。

## 决定

- `Agent` 和 `defineAgentConfig()` 默认创建并注册全部安全内置工具。
- `AgentConfigInput.tools` 改为 `extend` 与 `replace` 两种互斥模式。
- `extend` 是默认模式，按“默认内置、禁用、覆盖、追加”的固定顺序解析。
- `disabledBuiltins` 只接受公开的 `BuiltinToolName`。
- `overrides` 只覆盖已知内置工具，且覆盖实现必须保持相同工具名。
- `additional` 只用于新名称；任何名称冲突都在配置阶段报错。
- `replace` 完全跳过内置集合，只使用调用方给出的 `tools`。
- `additional`、`overrides` 和 `replace.tools` 直接接受 `defineTool()` 结果，Agent 先归一化再检查重名并冻结。
- 内置工具工厂继续公开，支持直接 Harness 测试和定制实现，但默认启用不再要求 Runtime 导入。
- 当前仅自动装载不依赖外部服务、文件或进程权限的时间与计算器；天气和定位仍属于应用工具。

## 备选方案

### 继续要求 Runtime 显式注册

兼容现有数组 API，但“内置”只能表示代码随包发布，不能提供开箱即用能力，每个应用都重复同样组装代码。

### 自定义工具同名时自动覆盖

写法较短，但工具名拼写或重复注册会悄悄改变执行实现。权限、Schema 和副作用也可能随之改变，因此要求通过
`overrides` 显式表达意图。

### 使用一个 enabled 布尔值

可以开启或关闭全部内置工具，却不能清楚表达禁用单项、覆盖单项和追加工具，也不利于以后扩展内置集合。

## 后果

正面影响：

- 最小 Agent 自动具备稳定的时间和计算能力。
- Runtime 只维护真正属于应用的工具。
- 禁用、覆盖、追加和整体替换在类型与运行时都有明确语义。
- 新增安全内置工具时，普通应用无需修改组装代码。

代价与限制：

- 原 `tools: AgentTool[]` 写法需要迁移为 `tools.additional` 或 `mode: 'replace'`，但不需要额外转换工具。
- 新增默认内置工具属于可观察行为，必须经过协议评审并同步更新 `BuiltinToolName`、测试和文档。
- 自动注册不是安全沙箱；工具级与 Runtime 全局 ToolGuard 仍决定工具是否获准执行。
